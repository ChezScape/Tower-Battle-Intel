# v4.11z26 Battle Report Schema Notes

## Why this matters

The app-side Battle Report data shows three different concepts that TBI should keep separate:

| App concept | TBI meaning |
|---|---|
| Enemies Hit By | Enemy touched/affected by something. Not necessarily a kill. |
| Enemies Destroyed By | Kill-source category. |
| Killed With Effect Active | Enemy died while an effect was active. Not necessarily killed directly by that effect. |

This prevents bad analysis such as treating Black Hole hit counts as Black Hole kill counts.

## Key parser improvement

The schema now includes observed fields for newer enemy categories:

- Saboteurs
- Commanders
- Overcharges

These should be optional parser fields so old reports still load cleanly.

## Guardian future value checks

Guardian fields exist for damage, summons, stolen/fetched coins, catches, gems, medals, shards, and module drops.
TBI can later use these in Systems and Command Deck, but they should stay optional until enough real samples include them.

## Confidence model

Use `game-file-confirmed-label` for visible/readable labels.
Use `game-file-observed` for metadata/schema field names.
Use `game-file-observed-medium-high` for strong practical interpretations like `DestroyedByOther`, but avoid claiming every exact internal source.
